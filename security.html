Security

Security information

Report suspected vulnerabilities privately to support.ashbizcon@mohitguruji.com. Do not submit exploit details, credentials, customer content, or sensitive tenant data through public channels.

Security boundaries

  • Confluence reads respect Atlassian authorization and the app's reviewed Forge scopes.
  • Public URL validation treats destinations as untrusted input and applies bounded request controls.
  • Persisted operational evidence is limited to settings, history, repair audit, scheduling, and related product evidence.
  • Confluence writes are limited to the reviewed Safe Repair workflow and fail closed on stale or conflicting page state.

Safe Repair protections

Repair uses server-side preflight, page version and body-hash evidence, explicit confirmation, a fresh page read before mutation, conflict detection, per-page audit evidence, and post-repair verification. LinkOps does not perform unattended scheduled repair.

External validation controls

LinkOps accepts HTTP/HTTPS only, rejects credential-bearing URLs, blocks local/private/metadata-style targets and non-standard ports, re-checks redirect targets, and uses bounded redirects, timeouts, retries, deduplication and concurrency. External validation can be disabled by administrators.

Forge scopes

  • read:page:confluence
  • write:page:confluence
  • storage:app

LinkOps requires backend external egress to validate arbitrary public URLs referenced by customer Confluence content and therefore must not claim Runs on Atlassian eligibility while that architecture remains in use.
